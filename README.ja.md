# claude-subagent-routing

[English](README.md) | [中文](README.zh.md) | **日本語**

Claude Code サブエージェントの静的モデルルーティング：ポリシー表 1 枚、モデル固定エージェント 2 つ、deny フック 1 本（ロジック約 15 行）。分類器なし、プロキシなし、フレームワークなし——そして 26 日間のシングルユーザー本番実測（n=1）。

Claude Code のこの領域に馴染みがない人向けの一息バージョン：Claude Code は作業中、コード検索や一括編集のような脇仕事のために、静かにヘルパー AI——*サブエージェント*——を雇います。デフォルトでは、どのヘルパーもメインセッションのモデル単価で課金される。メインが高価なモデルなら、インターンの仕事にシニアの時給を払っている状態で、画面には何の表示も出ません。この repo はインターンの仕事をインターン価格のモデルに固定し、ミスの手前にゲートを一枚立てます。使い方は変わらない。請求だけが変わる。

**まずレシートから**（7/3–8/3：導入前ベースライン 6 日間 + システム稼働 26 日間——サブエージェント 4.97 億トークン、単一ユーザー、混合の実ワークロード。細則は[監査コマンド](audit/audit-commands.md)に）：

| 指標 | 導入前 (7/3–7/8) | 固定期 (7/9–7/15) | 強化期 (7/16–8/3) |
|---|---|---|---|
| 単価（$ / 100 万トークン） | 3.98 | 1.94 | **1.31** |
| フロンティアモデル（Fable）のサブエージェントトークン占有率 | 41.5% | 29% | **0.28%**（19 日間で 7 assistant turn、すべて名指しの起動） |
| `scout` の 1 回あたり平均出力 | — | 282 tok | 167 tok（`effort: low`、−41%） |

**この repo が刺さる人**：Claude Code のメインスレッドを Opus か Fable で回し、日常的にサブエージェントへ仕事を投げている人——私の強化期ウィンドウでは、サブエージェントが入出力トークン全体の約 15% を占め、着地したモデルの単価で課金されていました。メインが元々 Sonnet だけなら、手法だけ star してください。金額はあまり動きません。インストール前に 30 秒、自分のモデル構成を確認：[audit §2](audit/audit-commands.md) のコマンドをコピペするだけです。

累計：旧構成で回した場合より約 **$1,100 の削減**——実績 $882 vs 反実仮想 $1,978（497M トークン × ベースライン単価 $3.98。オーダー感であり、請求書ではありません）。単一ユーザー、サブスクリプション枠の API 定価換算、品質は自己申告のみ：26 日間毎日使って、全部単一モデルで回した場合との違いは感じ取れませんでした。残りの細則——当時価格、キャッシュ係数、分母の正確な定義——はすべて[監査コマンド](audit/audit-commands.md)の隣に置いてあり、全数字を自分のディスクのトランスクリプトで再実行できます。

## 誰も監査しないデフォルト値

Claude Code のサブエージェントは、エージェント定義にモデルが固定されておらず、起動時に明示的な `model` も渡されない場合、セッションのモデルを継承します。メインが Sonnet ならこのデフォルトは無害。メインが Opus や Fable なら、「ちょっと grep してきて」のファンアウト全てがフロンティア価格で課金されます。

これはニッチな不満ではありません。[anthropics/claude-code#27665](https://github.com/anthropics/claude-code/issues/27665) には、Max 契約ユーザーが 17 日間で **93.8% のトークンを Opus に流した（定価換算 $1,246）** 記録があります。デフォルトのパイプラインに下位モデルへ振り分ける仕組みがないためで——この issue が最初に提案する対策こそ、本 repo のテーマそのもの：サブエージェントに高価なセッションモデルをデフォルト継承させるな、です。2026-08-03 時点でオープン、公式回答なし。

私のバージョンの事故：ルーティング表は 7 月 9 日に稼働開始しましたが、一箇所だけ甘い部分がありました——判断ティアが「メインスレッドを継承」のままで、この規則を書いた当時のメインは Opus でした。その頃には常用メインは Fable 5（$10/$50——Opus の 2 倍）に移っていた。何も壊れず、何も警告しない。6 日目の初回検収監査で、Fable サブエージェントが当該ウィンドウの**サブエージェントトークンの 31%、支出の 73%** を占めていたことが判明——完全未ルーティングのベースライン（41.5%、表の導入前列）よりは低いものの、依然として最大の費目が、一本の古びた仮定の上に乗っていました。同日中に：判断ティアを明示 opus に固定、フックを導入。（表の固定期 29% は丸 7 日間の平均です——固定後初日の 7 日目が、6 日目監査の 31% より平均を押し下げています。）

## 先行プロジェクト、正直版

このニッチには実プロジェクトが存在します。ただし、どこにも見つからなかったもの：本番環境の数字。

| プロジェクト | 概要 | 強制機構 | 追加の分類器 | 公開実測 |
|---|---|---|---|---|
| [pilotfish](https://github.com/Nanako0129/pilotfish) | ロールエージェント 8 種、frontmatter でモデル固定、オーケストレーションポリシー | なし——助言のみ。インストールは委譲を保証しないと README 自ら明記 | なし | ベンダーのベンチマーク引用、自前の本番データなし |
| [oh-my-claudecode](https://github.com/yeachan-heo/oh-my-claudecode) | 大規模マルチエージェントスイート | ドキュメント未確認 | なし | 30–50% 削減を謳うがデータは見当たらず |
| [claude-model-router-hook](https://github.com/tzachbon/claude-model-router-hook) | フック 3 本。プロンプト分類、起動書き換え | spawn パラメータの書き換え | キーワードヒューリスティック + 任意の Haiku フォールバック | なし |
| [claude-model-router](https://github.com/junoseong/claude-model-router) | API ルーター + deny 式 Claude Code フック | Deny + 再発行 | LLM（Haiku）分類器 | 合成 1000 プロンプトのコストモデル + 実測 17 件 |
| 監査ツール（[ccost](https://github.com/toolsu/ccost)、[token-dashboard](https://github.com/nateherkai/token-dashboard) など） | ローカルトランスクリプトのコスト分析 | — | — | 支出は測るがポリシーは知らない |

*2026-08-03 に各プロジェクトの公開 README を調査——時点情報です。訂正は issue へどうぞ。*

つまり：フレームワークはルーティングするが強制しない。フックルーターは強制するが分類器を持ち込む。監査ツールは測るがルーティングしない。この repo は欠けていた組み合わせ——**ポリシー + 強制 + 測定、分類器なし**——プラス、レシート。

## システム本体：三層防御 × 二次元ルーティング

**第一層——ルーティング表**（[policy/claude-md-block.md](policy/claude-md-block.md)）を `CLAUDE.md` に貼る：

| 仕事の種類 | エージェント | モデル | Effort |
|---|---|---|---|
| 読み取り専用の偵察（走査/検索/読解/要約） | [`scout`](agents/scout.md) | haiku | low |
| 機械的実行（方針決定済み、手を動かすだけ） | [`worker`](agents/worker.md) | sonnet | medium |
| 判断（レビュー/設計/リサーチ） | general-purpose | 明示 opus | セッション |

モデルはエージェントの frontmatter——エージェントファイル冒頭の設定ブロック——に固定されているので、誰もこの表を意識していない時も効き続けます。第二の次元は見た目以上に効きます：`effort: low` だけで scout の出力トークンが 41% 減、偵察タスクでは体感品質の低下なし。

**第二層——判断ティア内の振り分けは、オーケストレーター自身がやる。** 軽い判断（単一ファイルのレビュー、コピーの確認、二択）は sonnet 指定。重い判断（アーキテクチャ、複数ファイル横断レビュー、オープンエンドな設計）は opus 指定。迷ったら opus。これがこのシステムの「動的ルーティング」部分で、インフラは一切不要——後述の通り。

**第三層——機械のゲート**（[hooks/agent-model-guard.sh](hooks/agent-model-guard.sh)）——PreToolUse フック、つまり Claude Code がツール呼び出しを通す前に走らせるスクリプトです。Claude がモデルを告げずにヘルパーを雇おうとすると、フックはリクエストを**差し戻し**、拒否メッセージにルーティング表を添える。Claude はモデル付きで再送します。規則は習慣を防ぎ、ゲートはミスを防ぐ。

安いティアを健全に保つエスカレーション規則：安いティアが一度しくじったら、一段上げて再発行。同じティアでの再試行はしない。

## インストール

ファイル 3 つ、settings 設定 1 箇所、ポリシー 1 ブロック。この repo の clone 内で実行（フックは `jq` に依存——`command -v jq` で確認を）：

```bash
mkdir -p ~/.claude/agents ~/.claude/hooks
cp agents/scout.md agents/worker.md ~/.claude/agents/
cp hooks/agent-model-guard.sh ~/.claude/hooks/ && chmod +x ~/.claude/hooks/agent-model-guard.sh
```

`~/.claude/settings.json` では——**既存の `hooks.PreToolUse` 配列がある場合はそこにマージしてください。ファイルごと上書きしないこと**：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Agent",
        "hooks": [{ "type": "command", "command": "bash \"$HOME/.claude/hooks/agent-model-guard.sh\"", "timeout": 5 }]
      }
    ]
  }
}
```

（`command` の絶対パスは実戦検証済みの形。`timeout` は、フックが固まっても起動を巻き込まないための保険です。）

その後、[policy/claude-md-block.md](policy/claude-md-block.md) のポリシーブロックをあなたの `CLAUDE.md` へ。`effort` frontmatter キーは[公式 sub-agents ドキュメント](https://code.claude.com/docs/en/sub-agents)に記載があります。

issue を立てる前に読むと救われる注意点：

- **インストール後は Claude Code を再起動**——エージェント定義はセッション開始時に読み込まれます。
- **`CLAUDE_CODE_SUBAGENT_MODEL` は未設定のまま**——frontmatter をグローバルに上書きし、固定を静かに無効化します。
- **エージェント名はプロジェクト優先で解決。** プロジェクトに独自の `scout`/`worker` があると `~/.claude/agents/` に勝ちます。この 2 つの名前は自分の環境で一意に保ち、独自の固定エージェントを足すならフックの許可リスト（`scout|worker|fork`）も拡張を。
- **フックが検証するのは起動リクエストであって、最終的に解決されたモデルではない。** 封じるのは「タグ忘れ」という failure mode——私の測定ではリークの全てがこれでした——であり、考えうる全ての設定ミスではありません。

スモークテスト：任意のセッションで、model を**指定せずに** general-purpose サブエージェントを起動するよう Claude に頼む。期待動作：起動が deny され、拒否理由にルーティング表が表示され、Claude がモデル付きで再発行する。Claude Code 2.1.210（2026 年 8 月）で検証済み。一向に deny されない場合：`jq` の有無、settings.json のスクリプトパスの解決、matcher が正確に `Agent` かを確認——フックのペイロードスキーマはバージョン間でドリフトするため、2.1.210 から遠い場合は changelog と突き合わせてください。deny はされるが再発行されない場合、それはモデルの従順さの問題で、フックの問題ではありません。失敗モードは意図的にオープン設計：フック自体がクラッシュしてもエラー表示の上で起動は通ります——最悪ケースは素の挙動に戻るだけで、セッションが使えなくなることはありません。

インストールは以上。デーモンなし、プロキシなし、npm なし。

## 導入翌日から：何が変わるか

Claude への話しかけ方は、何も変わりません。普段どおり頼めば、ポリシーブロックが委譲を捌きます：

- 「retry ロジックはどこで定義されてる？」→ Claude は `scout` を送る——Haiku、読み取り専用——file:line が返ってくる。
- 「このリネームをリポジトリ全体に適用して」→ `worker`——Sonnet、手を動かすだけ、設計判断はしない。
- 「この diff をちゃんとレビューして」→ general-purpose エージェント、明示 opus 指定。

手動で名指ししても構いません：「まず scout に auth モジュールを偵察させて」「worker に spec どおり直させて」——エージェント名は、あなたと Claude の共通語彙になります。

ゲートが発火すると、トランスクリプトにはこう出ます——エラーではなく、差し戻しです：

> agent-model-guard: this Agent call has no model and would silently inherit the main-thread model. Re-issue it with an explicit model per the routing table: judgment → opus, light judgment → sonnet, read-only recon → haiku. …

Claude はそれを読み、モデル付きで再発行し、作業は続きます。ほとんどの場合、*発火しない*ことに気づくはず——それが狙いです。

月に一度（設定を変えた後も）、[audit §2](audit/audit-commands.md) を再実行して 2 つの数字を確認：サブエージェントトークンに占めるフロンティアモデルの割合（名指ししていない限りほぼ 0 のはず）と、モデル構成が想定どおりの方向に動いているか。

## 手法（もう一度やるとしても同じやり方をする部分）

1. **デフォルト値を監査する。** 「継承/デフォルト」の挙動には、環境が変わると静かに壊れる仮定が必ず埋まっています。コスト削減の最初の一手は安いモデルへの乗り換えではなく、静かに効いている高価なデフォルトを見つけ出すこと。
2. **固定は裁量に勝る。** この削減は、より良い判断をしたからではなく、判断そのものを削除したから生まれました。覚えていないと効かない規則は、規則ではない。
3. **ミスはゲートで塞ぐ。** プロンプトレベルの規則（CLAUDE.md）は信頼できるが柔らかい。十数行のフックが「タグ忘れ」という failure mode を溶接して塞ぎます。
4. **データでループを閉じる。** 稼働前に指標を決め（単価、リーク回数、モデル占有率）、同じコマンド群で定期的に再測定し、直感に反するシグナルは分解してから結論を出す。例：sonnet の平均出力が稼働中に跳ねた——effort ティアの故障ではなく、軽い判断タスクが sonnet レーンに合流して母集団が変わっただけ。ノブを疑う前に、母集団を分解する。

## あえて作らなかったもの

- **分類器なし。** 上の表のフックルーター 2 つはどちらも、タスク難易度を判定する分類器（キーワードヒューリスティックか追加の Haiku 呼び出し）を足しています。しかしオーケストレーターは*タスクのプロンプトを自分で書いた*張本人——その仕事が偵察か、機械的作業か、判断かは既に知っています。静的ルーティング + オーケストレーター自身のティア振り分けで価値は取り切れる。分類器は、既に無料で起きている判断を複製し、誤分類の面を増やすだけです。
- **書き換え式の強制なし。** Deny→再発行はオーケストレーターをループ内に留め、他のフックとも安全に共存します。`updatedInput` による spawn パラメータの書き換えは、複数フック発火時のマージ順序が未文書化（router-hook プロジェクト自身の README が認めています）。収束する証拠：junoseong の deny 式フックはテストタスクで **25.3k → 11.4k トークン** を計測。
- **ティアの細分化なし。** 強化後に残る伸び代は小銭拾いです。ティアを増やすたびに、数セントの上振れのために分類負担と誤ルーティング面が増える。
- **クロスベンダーのプロキシなし。** [claude-code-router](https://github.com/musistudio/claude-code-router) の類が解くのは別の問題（バックエンドの差し替え）です。本システムは単一ベンダー・単一サブスクリプションの内側に留まる——上の数字がクリーンなのは、まさにそのおかげです。

## 既知の穴

- **ワークフロー内の `agent()` 呼び出しは Agent フックを素通り**（PreToolUse が発火しない）。ポリシーブロックによるソフト制約のみ。実測リーク：19 日間で 7 回 ≈ $6——ゲートを作る価値なし。
- **`fork` エージェントは設計上の適用除外**——継承こそが fork の意味論で、model パラメータは no-op。
- **未解決の問い**：opus ティアが依然サブエージェントトークンの約 52% を占める。タスク構成のせいか、軽判断の振り分け不足か？次回の再測定で判明。
- **9 月に再測定を予定**：Sonnet の期間限定価格が 9/1 に終了（$2/$10 → $3/$15）、単価は機械的に約 20% 上がります。それは定価の変動でありルーティングの退化ではない——将来の数字が誤読されないよう、いま書いておきます。
- モデルエイリアス（`opus`、`sonnet`、`haiku`）は前方解決：稼働中に `opus` エイリアスが同価格の新 Opus を指すようになりました——今回は無料アップグレードでしたが、決定論が必要なら具体的なモデル ID を固定してください。
